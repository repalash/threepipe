# PR Diff Viewer: work stream

A running log of what was asked and what was done, numbered so nothing gets lost. Newest items at the bottom of
each list. Status: ✅ done (commit), 🔨 in progress, 📋 planned, 💤 parked.

## Done

1. ✅ JetBrains-style side-by-side diff: unaligned editors, both line numbers in the middle divider, curved
   connectors, synced scrolling; Material Darker colors; works on phones (`7aa0ef7`).
2. ✅ The IDE's diff settings (gear): Align Changes, Synchronize Scrolling, Ignore Differences, Highlighting
   Differences, collapse unchanged, soft wrap; unified viewer; Log tab with graph, filter, ranges (`7aa0ef7`).
3. ✅ The IDE's PR view: title, "Changes from N commits ▾" (searchable), blue unviewed dots, Viewed sync with GitHub,
   the repository's PR list with filters (`87f007d`).
4. ✅ Diff bands, insertion lines and curves matched pixel by pixel to the IDE; a cog for settings; editor font
   shortcuts Ctrl/⌘ + = − 0 (`21050ca`, `bc504b1`).
5. ✅ Search Everywhere (double Shift): files, actions and settings (ON/OFF), commits, PRs; IDE-style fuzzy match
   (`b17928a`).
6. ✅ Colors from the IDE scheme (Material Theme UI Lite); full-width IDE selection (`8798bb2`).
7. ✅ Theme picker: the 10 Material variants, generated by `tools/material-themes.mjs` (`a5e34e2`).
8. ✅ Snapshot mode: `?snap=<name>` answers from recorded API responses, to try a PR on a phone with no token;
   `tools/record-snapshot.cjs` records one (`306b9e7`).
9. ✅ Quick edits: a pencil over the diff makes the PR head editable, bands follow the edit; a Commit panel like the
   IDE's (file checkboxes, message, Amend last commit, Commit and Push) commits to the PR's branch through the Git
   Data API, refused if the branch moved, with Undo; edits kept for the tab's session (`0690cd2`).

10. ✅ PR description and conversation: "View Timeline" in the PR header opens a Timeline tab: the description as
    GitHub renders it, comments, reviews with their inline comment threads (click a path to open the file), and the
    commits (click to open one), in time order.
11. ✅ Markdown preview in the diff: `.md` files show rendered (new files as one page; modified files as old | new
    with the changed blocks marked, synced scrolling; F7 steps through the changed blocks); a `</>` / preview
    toggle; editing switches to the code.
12. ✅ Markdown in commit messages: the Log's commit details render the body as Markdown, trailers
    (Co-Authored-By …) one per line. The PR description is GitHub's own rendering (item 10).

13. ✅ Settings split: the titlebar gear has the app's settings (theme, editor font, token, open another PR), the
    diff gear only the diff's (align, sync, ignore, highlighting, collapse, soft wrap, Markdown preview, open on
    GitHub).
14. ✅ Markdown rich diff: changed words highlighted inside the rendered text (inserted green, removed struck
    through); old | new with connectors between the changes and change-aligned scrolling; one page on phones with the
    removed words and blocks put back; a legend; no side bar on changed blocks (it read as a quote).
15. ✅ *Preview | Code* toggle in the toolbar for Markdown files (also in the diff gear and Search Everywhere).
16. ✅ "Open on GitHub" says what it opens: *Open PR on GitHub*; the file button offers the new version (head), the
    old version (base), or the file's diff on GitHub.
17. ✅ The project chip is a menu (this repo's PRs, open another PR in a dialog, recent PRs, start page); the folder
    button left the strip.
18. ✅ A × next to "Changes from: commit …" goes back to all commits.
19. ✅ PR search in a snapshot filters the recorded list (a snapshot has no search API).
20. ✅ Inline icons in messages no longer break the line.
21. ✅ Tabs close with × (Log, Timeline); Show Log from the commits menu or Search Everywhere brings the Log back.
22. ✅ The Changes strip button works from the Commit panel.
23. ✅ Tooltips show after 0.3 s (custom; the browser's take over a second).
24. ✅ The status bar follows the tab in front: the file (language, +/−, difference) in the diff, the commit count and
    selection in the Log, the PR and its comment counts in the Timeline.
25. ✅ Double-click a file in the tree brings the diff tab to the front (a tap does on a phone).

26. ✅ Commit Options (gear in the Commit panel): author and committer name and email, kept in this browser; "Use my
    account" fills in the token's account (its noreply email when the email is private). Unset, GitHub uses the
    token's account; Amend keeps the commit's author unless one is set.
27. ✅ The Commit panel's tree highlights the file that is open.

28. ✅ QA pass by a separate agent (13 findings), all fixed:
    - edits are kept per PR with the head they were made on: opening another PR and coming back keeps them; after
      the head moves (a commit here, its undo, a push elsewhere) the edits of unchanged files carry over, others are
      dropped with a message naming them; Undo puts the committed edits back (as the IDE's Undo Commit);
    - on a single commit or range the edits are hidden (kept), and the Commit panel says how to get back to them;
    - phone: the diff toolbar fits (the viewer switch is in the diff gear), Commit Options fits;
    - Markdown: marks never enter a link address; changed code in a fence shows its old lines as a struck block after
      it (one page) instead of running text together; differences counted per change (same as the code view), a new
      file counts as one; a failed preview can be retried; listeners no longer pile up;
    - no duplicate actions in Search Everywhere; "Difference n of m" only for the view in front and kept across a font
      change; `uas` ranks UseAutosave first; picking a commit keeps the open file; README token text; per-PR UI state
      (unchecked files, closed tabs) resets on another PR.

29. ✅ Offline app: a service worker (`sw.js`) keeps the page, Monaco, Shiki, Markdown and fonts, and every GitHub
    response the page fetched (network first, the saved copy when offline or slow; an "Offline" badge says so).
    Installable (manifest, icons; Add to Home Screen). Monaco's worker starts from the page's origin so it works
    offline too.
30. ✅ Download for offline (titlebar gear → Offline, or Search Everywhere): a repository's open PRs (or one) with
    their files, contents, each commit's changes, conversations and avatars, the PR lists, and the grammars they need;
    progress, Stop, Update, Remove, storage used. Downloaded PRs are listed on the start page.
31. ✅ Offline edits and Viewed: edits are kept in localStorage (they survive closing the browser); Commit and Push
    offline says to retry online; Viewed marks made offline are sent to GitHub on the next online load.

## Notes

- The diff algorithm is Monaco's (VS Code's), not JetBrains'.
- GitHub GraphQL (Viewed sync) is untested against the real API in this environment.
- Snapshots of private repositories hold their code: `snap/` is git-ignored, never commit one.
