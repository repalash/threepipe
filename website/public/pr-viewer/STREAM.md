# PR Diff Viewer: work stream

A running log of what was asked and what was done, numbered so nothing gets lost. Newest items at the bottom of
each list. Status: ✅ done (commit), 🔨 in progress, 📋 planned, 💤 parked.

## Done

1. ✅ JetBrains-style side-by-side diff: unaligned editors, both line numbers in the middle divider, curved
   connectors, synced scrolling; Material Darker colors; works on phones (`7aa0ef7`).
2. ✅ The IDE's diff settings (gear): Align Changes, Synchronize Scrolling, Ignore Differences, Highlighting
   Differences, collapse unchanged, soft wrap; unified viewer; Log tab with graph, filter, ranges (`7aa0ef7`).
3. ✅ The IDE's PR view: title, "Changes from N commits ▾" (searchable), blue unviewed dots, Viewed sync with GitHub,
   the repository's PR list with filters (`87f007d`).
4. ✅ Diff bands, insertion lines and curves matched pixel by pixel to the IDE; a cog for settings; editor font
   shortcuts Ctrl/⌘ + = − 0 (`21050ca`, `bc504b1`).
5. ✅ Search Everywhere (double Shift): files, actions and settings (ON/OFF), commits, PRs; IDE-style fuzzy match
   (`b17928a`).
6. ✅ Colors from the IDE scheme (Material Theme UI Lite); full-width IDE selection (`8798bb2`).
7. ✅ Theme picker: the 10 Material variants, generated by `tools/material-themes.mjs` (`a5e34e2`).
8. ✅ Snapshot mode: `?snap=<name>` answers from recorded API responses, to try a PR on a phone with no token;
   `tools/record-snapshot.cjs` records one (`306b9e7`).
9. ✅ Quick edits: a pencil over the diff makes the PR head editable, bands follow the edit; a Commit panel like the
   IDE's (file checkboxes, message, Amend last commit, Commit and Push) commits to the PR's branch through the Git
   Data API, refused if the branch moved, with Undo; edits kept for the tab's session (`0690cd2`).

10. ✅ PR description and conversation: "View Timeline" in the PR header opens a Timeline tab: the description as
    GitHub renders it, comments, reviews with their inline comment threads (click a path to open the file), and the
    commits (click to open one), in time order.
11. ✅ Markdown preview in the diff: `.md` files show rendered (new files as one page; modified files as old | new
    with the changed blocks marked, synced scrolling; F7 steps through the changed blocks); a `</>` / preview
    toggle; editing switches to the code.
12. ✅ Markdown in commit messages: the Log's commit details render the body as Markdown, trailers
    (Co-Authored-By …) one per line. The PR description is GitHub's own rendering (item 10).

## Planned

13. 📋 Git operations from the Log's context menu, first batch (no merge needed): Copy Revision Number, View in
    browser, Create Patch, Go to Parent / Child, New Branch / Tag, Compare with PR head, Edit Commit Message (F2),
    Squash / Fixup into the previous commit, Undo Commit (head), Reset Current Branch to Here. All rewrites check the
    branch first and offer Undo.
14. 📋 GitHub-style URLs, as github.dev does: replace `github.com` in a PR / commit / compare link with the viewer's
    address, e.g. `…/pr-viewer/<owner>/<repo>/pull/<n>/files`. Needs the host to serve the page for any path under
    `/pr-viewer/` (a 404 fallback that forwards the path to `?pr=` works on static hosts).

## Notes

- The diff algorithm is Monaco's (VS Code's), not JetBrains'.
- GitHub GraphQL (Viewed sync) is untested against the real API in this environment.
- Snapshots of private repositories hold their code: `snap/` is git-ignored, never commit one.
