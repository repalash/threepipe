# Audit: Pipeline / Buffer / Material Extension Plugins

## Summary

Most webgi pipeline / buffer / material-extension plugins have direct counterparts in threepipe core or in the `experiments/threepipe-webgi/` overlay. The threepipe versions are generally cleaner ports (typed `MaterialExtension`, `MaterialUserData` augmentations, `updateMaterialDefines`, `uiFolderContainer`, `AViewerPluginSync` lifecycle, `ThreeSerialization`, `assetManager.registerGltfExtension`). The big architectural shift is that webgi's `GenericFilterPlugin` / `MultiFilterPlugin` were replaced by threepipe's `PipelinePassPlugin` (single pass) — there is no port of `MultiFilterPlugin`, but no consumer of that base remains in scope. `GenericExtensionPlugin` from webgi is also not ported (its dep was `CombinedPostPlugin`, which is gone in threepipe).

Plugins missing entirely: `FlatMaterialExtensionPlugin`, `LayeredMaterialPlugin`, `ThinFilmLayerPlugin`, `TriplanarUVMappingPlugin`, `AutoUVMappingPlugin`, `XAtlasPlugin`. `AnisotropyPlugin` is only in the experiment overlay (not core). `VelocityBufferPlugin` is only in the experiment overlay.

A handful of carry-over bugs and divergences were identified — most notably that the threepipe `GBufferPlugin` does not currently register its `unpackExtension` on `gbuffer`-marked override materials (FragmentClipping/Clearcoat/etc. won't run for the gbuffer pre-pass the way they did in webgi), the `NoiseBumpMaterialPlugin` defaults a `flakeScale` of `0.05` while the uniform default is `1000` (carried from webgi), and there is a known-disabled `unregisterMaterialExtensions(unpackExtension)` path on `_disposeTarget` in both `GBufferPlugin` and `DepthBufferPlugin`.

## webgi-only (missing)

- **FlatMaterialExtensionPlugin** — overrides `gl_Position` to make a material draw flat in screen space; depends on `GBufferPlugin` and registers extension on `getPlugin(GBufferPlugin)?.material` (legacy `screenPass.material` registration is now done by `GBufferPlugin._createTargetAndMaterial` in threepipe so the equivalent hook exists). No threepipe equivalent.
- **LayeredMaterialPlugin** — patches `lights_physical_fragment` to mix in a "cavity" color/roughness/metalness driven by SS curvature derivative (uses `sscurvature.glsl`). gltf extension `WEBGI_materials_layered`.
- **ThinFilmLayerPlugin** — voronoise-based hue-shifted noise overlay; uses `randomHelpers.glsl`, `voronoise.glsl`, `thinFilmLayer.glsl`, `hsvHelpers.glsl`. gltf extension `WEBGI_materials_thin_film_layer`.
- **TriplanarUVMappingPlugin** — patches `bumpmap_pars_fragment`, `map_fragment`, `roughnessmap_fragment`, `metalnessmap_fragment`, `normal_fragment_maps` and adds vertex-side `vWorldPosition`, `vLocalPosition`, `vWorldNormal`, `vLocalNormal`. gltf extension `WEBGI_materials_triplanar`. Also note `worldpos_vertex` block was duplicated/conditionalized — be careful about the negation it adds (it relies on *not* having `USE_ENVMAP`/`DISTANCE`/`USE_SHADOWMAP`/`USE_TRANSMISSION` while still emitting `worldPosition`).
- **AutoUVMappingPlugin** — generates UVs in vertex shader from `position`/`normal`/bounding-sphere center; supports cylindrical/spherical/conical/box/octagonal modes plus axis. Special-cases `DiamondMaterial` markers `#glMarker diamondUvFlag1/2`. gltf extension `WEBGI_materials_auto_uv_mapping`.
- **XAtlasPlugin** — uses `xatlas-three` UVUnwrapper with `xatlasjs` wasm at runtime. There is no public threepipe wrapper; only `xatlas-web` exists deep inside `plugins/path-tracing/node_modules/three-gpu-pathtracer/...` (a transitive dep, not exposed).
- **AnisotropyPlugin (core)** — present only in the experiment overlay (`experiments/threepipe-webgi/src/plugins/extras/AnisotropyPlugin.ts`); not in `src/plugins/material/`. If this is intended to ship with core, the experiment version is the source of truth.
- **VelocityBufferPlugin (core)** — same as above; only in the experiment overlay. Note three.js core now provides `KHR_materials_anisotropy`-aligned `anisotropy` on `MeshPhysicalMaterial`; the WEBGI extension is intentionally separate (rotation/direction texture modes + noise + progressive integration).
- **GenericExtensionPlugin / MultiFilterPlugin** — base classes intentionally retired; threepipe's `MaterialExtension` API + `assetManager.materials.registerMaterialExtension` is the replacement for the former; threepipe pipeline is simpler so the latter is unnecessary.

## threepipe-only (new features)

- `DepthBufferPlugin` (`src/plugins/pipeline/DepthBufferPlugin.ts:42`) — separate render-target plugin with its own `unpackExtension` and `MeshDepthMaterialOverride`. Allows e.g. RGBA-packed depth without the gbuffer flags pass.
- `FrameFadePlugin` (`src/plugins/pipeline/FrameFadePlugin.ts`) and `SSAAPlugin` (`src/plugins/pipeline/SSAAPlugin.ts`).
- `GBufferPlugin.unpackExtension` (`src/plugins/pipeline/GBufferPlugin.ts:87-124`) replaces the legacy ad-hoc `getUnpackSnippet()` + `updateShaderProperties` workflow. It auto-registers on `screenPass.material` when `isPrimaryGBuffer` (`src/plugins/pipeline/GBufferPlugin.ts:180-185`) and exposes `tNormalDepth`, `tGBufferFlags`, `tGBufferDepthTexture` uniforms plus `HAS_*` defines.
- `GBufferMaterial.flagUpdaters` is a keyed `Map<string, ...>` (`src/plugins/pipeline/GBufferMaterial.ts:61`) instead of webgi's `[]` — supports unregistration by key (`src/plugins/pipeline/GBufferPlugin.ts:272-278`).
- `GBufferPlugin` adds `IObject3D.customGBufferMaterial` override and threads `pluginsDisabled`/`renderToGBuffer` via `forcedOverrideMaterial` (`src/plugins/pipeline/GBufferPlugin.ts:214-241`).
- `GBufferPlugin.target` is created with `wrapS/wrapT = ClampToEdgeWrapping` — webgi did not set this (`src/plugins/pipeline/GBufferPlugin.ts:154-155`).
- `GBufferPlugin` supports zPrepass-aware MSAA (`src/plugins/pipeline/GBufferPlugin.ts:144-145`); webgi always used `composerTarget.samples`.
- `NormalBufferPlugin.MeshNormalMaterialOverride` (`src/plugins/pipeline/NormalBufferPlugin.ts:135`) replaces webgi's transient transparent/transmission flipping in render() with proper `onBeforeRender`/`onAfterRender` reset state machine — much safer.
- `MaterialExtension`-ified `unpackExtension` (gbuffer + depth) carries `priority: 100` and `extraDefines` callbacks — a clean replacement for webgi `IShaderPropertiesUpdater`.
- gltf extensions (Clearcoat/Anisotropy/CustomBumpMap/NoiseBump/FragmentClipping) are now data-driven through `assetManager.gltfExtensions`/`registerGltfExtension` (`src/assetmanager/AssetManager.ts:579`), not via `loaderCreate` event listeners. Cleaner and unmounts deterministically in `onRemove`.
- `MaterialExtension.computeCacheKey` is consistently used in threepipe ports — webgi sometimes left it implicit.

## Bugs in webgi

These exist in the legacy webgi sources and you should NOT carry them forward verbatim if porting more.

- `ParallaxMappingPlugin.ts:87-88`: substitutes `PARALLAX_MAP_STEPS`/`PARALLAX_MAP_B_STEPS` from `this._defines` — but `_defines` only contains `PARALLAX_NORMAL_MAP_QUALITY`. `@matDefine` writes to `materialObject.defines`, not `this._defines`. Result: shader gets the literal string `undefined` substituted (or whatever the renderer's defines have). threepipe's port (`src/plugins/material/ParallaxMappingPlugin.ts:87-88`) correctly uses `this.stepCount.toString()`.
- `NormalBufferPlugin.ts:100`: `viewer.renderer.disposeTarget(this._normalTarget?.dispose?.() as any)` — calls `dispose()` on the target (which returns void) and then passes that void into `disposeTarget`. The actual target is never passed. threepipe's port disposes correctly (`src/plugins/pipeline/NormalBufferPlugin.ts:75-78`).
- `VelocityBufferPlugin.ts:120`: same pattern — `disposeTarget(value?.dispose?.() as any)` disposes void. Fixed in the experiment port (`experiments/threepipe-webgi/src/plugins/buffer/VelocityBufferPlugin.ts:84-89`).
- `AnisotropyPlugin.ts:288-298`: the legacy plugin includes an `onMaterialUpdate`/`onRegister`/`onAddToMesh` block in the `materialExtension` literal — but webgi's `MaterialExtension` interface does not call these (they're defined on the threepipe-side interface). They're dead code in webgi.
- `AutoUVMappingPlugin.ts:97-98`: reads `userData[AutoUVMappingPlugin.PluginType]?._autoUvMapping?.mode/axis` — nested pluginType-keyed userData, but `addUVMapping()` writes to `userData._autoUvMapping` directly. The UI also writes via setter to the nested location. Net result: the plugin reads from the nested per-pluginType bucket while material setup writes to the flat key — UI changes update the shader but `addUVMapping`-driven defaults never reach the shader.
- `NoiseBumpMaterialPlugin.ts:288`: `flakeScale` default is `0.05`, but uniform default is `1000.0` (`NoiseBumpMaterialPlugin.ts:32`) and the UI bounds are `[100, 10000]` — newly-enabled materials will have a value way below the UI bound. Bug-for-bug copied to threepipe (`src/plugins/material/NoiseBumpMaterialPlugin.ts:51`).
- `LayeredMaterialPlugin.ts:34`: `cavityScale: {value: 1}` and `stepSize: {value: 1}` — but the shader doesn't use `stepSize` anywhere (only `cavityScale`). Dead uniform.
- `LayeredMaterialPlugin.ts:111`: `(shader as any).vertexUvs = true` — three.js no longer reads `vertexUvs` (replaced by `USE_UV` define).
- `FragmentClippingExtensionPlugin.ts:64`: shader uses `${FragmentClippingMode.Circle}` etc. via JS template-literal string interp — works but means the GLSL is evaluated at module load, before the plugin reads any user value. Threepipe's port avoids this with a literal-replacement pass over the loaded `.glsl` chunk (`src/plugins/material/FragmentClippingExtensionPlugin.ts:62-65`).
- `ClearcoatTintPlugin.ts:55-71`: relies on a 4-line raw `replace` (not `shaderReplaceString`) — silently no-ops if three.js core changes the spelling. Already detected with `console.error` warning. threepipe's port migrated to `shaderReplaceString` which throws cleanly (`src/plugins/material/ClearcoatTintPlugin.ts:69-76`).
- `XAtlasPlugin.ts:80`: progress callback is a `console.log` rather than a `uiConfig` progress event.
- `MeshOptSimplifyModifierPlugin.ts:36`: event name uses random suffix `+ 'a'` (literal `'a'`) — apparently to avoid leading numeric chars; threepipe's port drops the trailing `'a'` (`src/plugins/extras/MeshOptSimplifyModifierPlugin.ts:44`) — both use `Math.random().toString(36).substring(7)`. Substring(7) of a Math.random base-36 string can be empty (random has variable length). Both have the same risk; threepipe is slightly worse off here.

## Bugs in threepipe / threepipe-webgi

- **`GBufferPlugin._disposeTarget` cannot unregister `unpackExtension`** — at `src/plugins/pipeline/GBufferPlugin.ts:198`, `this._viewer.renderManager.screenPass.material.unregisterMaterialExtensions([this.unpackExtension])` is commented out with `// todo`. After plugin remove + re-add, the extension stays attached and the `extraUniforms` getters keep returning the new (or stale) values. Same bug in `DepthBufferPlugin._disposeTarget` (`src/plugins/pipeline/DepthBufferPlugin.ts:141`).
- **`GBufferPlugin._createTargetAndMaterial` does not register `unpackExtension` on `gbuffer`-marker materials** — webgi's `FragmentClippingExtensionPlugin` explicitly called `v.getPlugin(GBufferPlugin)?.material?.registerMaterialExtensions([this.materialExtension])` on add (`FragmentClippingExtensionPlugin.ts:296`). The threepipe ports of `FragmentClippingExtensionPlugin`, `ClearcoatTintPlugin`, `NoiseBumpMaterialPlugin`, `CustomBumpMapPlugin` have this commented out (e.g. `src/plugins/material/FragmentClippingExtensionPlugin.ts:199`). Combined with `GBufferMaterial.onBeforeRender` which only registers `material.materialExtensions` (`src/plugins/pipeline/GBufferMaterial.ts:142-144`) — the source-material's extensions do propagate to gbuffer rendering, but only if the source material is registered on the `materialManager`. In the gbuffer override path through `customGBufferMaterial`, however, the user's own override material is used and no auto-propagation happens. Audit candidate; not necessarily a regression but worth a verification pass.
- **Carried-over `flakeScale=0.05` default** — `src/plugins/material/NoiseBumpMaterialPlugin.ts:51`. UI bounds are `[100, 10000]`. Either the default or the slider bounds need correcting.
- **`FragmentClippingExtensionPlugin` `clipMode` / `clipInvert` undefined-undefined check** — `src/plugins/material/FragmentClippingExtensionPlugin.ts:48-49` reads `if (tf.clipMode === undefined !== undefined) tf.clipMode = ...` — `(undefined === undefined) !== undefined` is `true !== undefined` which is `true` always, so the assignment always runs — but only when `tf.clipMode` is undefined the condition would have been intended to fire. Effective behavior: it always re-defaults `clipMode`/`clipInvert` even when the caller passed values via `params`. Combined with `params && Object.assign(tf, params)` on the next line which then overrides — the net behavior accidentally works on creation but is incorrect for callers updating an existing extension. Likely a typo `=== undefined` was meant.
- **`FragmentClippingExtensionPlugin` array-typed `clipPosition` / `clipParams` mismatch** — at `src/plugins/material/FragmentClippingExtensionPlugin.ts:93-96`, when not Plane mode, it checks `Array.isArray(tfUd.clipPosition)` to decide how to copy `tfUd.clipParams`. The check is on the wrong field (`clipPosition` vs `clipParams`). Should be `Array.isArray(tfUd.clipParams)`.
- **`fragmentClippingGLTFExtension.name` mismatch with deprecated constant** — `src/plugins/material/FragmentClippingExtensionPlugin.ts:213` says deprecated constant `'WEBGI_materials_fragment_clipping_extension'` but `fragmentClippingGLTFExtension.name` is `'WEBGI_materials_fragment_clipping'` (line 276). glTF files saved by webgi use the longer name; the threepipe import path won't recognize them. Behavior divergence on glTF round-trip.
- **`fragmentClippingGLTFExtension.export` is wired to `glTFMaterialsFragmentClippingExtensionExport` (a function)** but the `gltfExtensions` registration is also missing the `textures` schema (set to `undefined`); fine, but inconsistent with `customBumpMapGLTFExtension` and `anisotropyGLTFExtension` which declare `textures: {…}` so AssetManager can collect them. Not a bug per se, but worth filing.
- **`NormalBufferPlugin.MeshNormalMaterialOverride` carries `bumpScale = 1`** in `reset()` (`src/plugins/pipeline/NormalBufferPlugin.ts:181`) — but the source material may have been a non-bumpy material, so this resets to a non-zero default and then conditionally copies. If the material has `bumpMap = null`, this is fine; but if the source material has `bumpMap` set but `bumpScale = 0` set later, the `if (material.bumpScale !== undefined) this.bumpScale = ...` always copies, so OK. No bug, just verbose.
- **`VelocityBufferPlugin._previousWorldMatrices` leaks** — `experiments/threepipe-webgi/src/plugins/buffer/VelocityBufferPlugin.ts:217` is a `Record<string, Matrix4>` keyed by `object.uuid`. Removed objects' previous matrices stay in the map indefinitely. Memory leak in long-lived sessions.
- **`VelocityBufferPlugin` first-frame race** — `experiments/threepipe-webgi/src/plugins/buffer/VelocityBufferPlugin.ts:104-107` initializes `lastProjectionViewMatrix` from `currentProjectionViewMatrix` only on the first call, but `_beforeRender` returns false when `frameCount > 0` (line 175). The class-extension is required because the `_firstCall` flag lives on the wrapped pass. This works, but if the camera changes between frame 0 and 1 you lose one frame of velocity. Minor.
- **`GBufferPlugin._beforeRender` super call commented out** — `src/plugins/pipeline/GBufferPlugin.ts:251-253` says `// camera.updateShaderProperties(this.material)` "this is done in the material now". The material does call `(camera as ICamera).updateShaderProperties(this)` in `onBeforeRender` (`src/plugins/pipeline/GBufferMaterial.ts:135`), so this is fine, but `cameraNearFar` will be picked from whichever camera renders the object — for the override-material code path through `customGBufferMaterial`, `currentMaterial` is used and the camera-near-far set by an override material's `onBeforeRender` may differ from what the screen pass expects.
- **`GBufferMaterial.onBeforeRender` registers/unregisters `materialExtensions` every frame, every object** — `src/plugins/pipeline/GBufferMaterial.ts:142-144` and `:193-194`. `registerMaterialExtensions` then `unregisterMaterialExtensions` on every onBefore/After can be expensive and may invalidate cached programs. Profile impact unknown; flag for review.
- **`MeshOptSimplifyModifierPlugin` produces non-indexed output** — `src/plugins/extras/MeshOptSimplifyModifierPlugin.ts:105` returns `iGeometryCommons.upgradeGeometry.call(geometry.toNonIndexed())`. Webgi returns the indexed geometry. After simplification you lose the index, doubling vertex count — this defeats the purpose of mesh simplification. Likely an oversight.
- **`AnisotropyPlugin` (experiment) — `_anisotropicDirection` typo in UI** — `experiments/threepipe-webgi/src/plugins/extras/AnisotropyPlugin.ts:284` reads `[state, '_anisotropicDirection']` but the data field is `_anisotropyDirection` (no `c`). UI slider does nothing.
- **`AnisotropyPlugin` (experiment) — gltf importer drops `_anisotropyDirectionMap` (resource form)** — webgi version handled both the inline-resource path (`anisotropyDirection.resource`) and indexed-texture path (`AnisotropyPlugin.ts:401-417`). The threepipe-webgi port (`AnisotropyPlugin.ts:449-458`) only handles the indexed-texture path; will fail on extra-resources-bundled glTF saved by older webgi.
- **`AnisotropyPlugin` (experiment) — gltf export omits `resources`** — the legacy webgi exporter produced a `resources` block for data-uri/http-rooted maps (`AnisotropyPlugin.ts:462-464`); the experiment port drops that branch (`AnisotropyPlugin.ts:493-498`). Inline data-uri textures will fail to round-trip.
- **`CustomBumpMapPlugin` (threepipe) — bicubic toggle decoration order** — `src/plugins/material/CustomBumpMapPlugin.ts:30-32` stacks `@uiToggle` then `@matDefine` then `@serialize`. Decorators evaluate bottom-up; with TS legacy decorators this matters. Verify `bicubicFiltering` actually round-trips through serialize and triggers `setDirty` (the same pattern is used in webgi at `CustomBumpMapPlugin.ts:29-31` and works, so likely fine).
- **`AnisotropyPlugin` (experiment) — no `customGBufferMaterial` propagation** — does not register on `GBufferPlugin.material`. If the project relies on tangents in gbuffer (unlikely) this is irrelevant; but worth noting parity with webgi which also did not register on gbuffer.

## Behavior divergences

- `GBufferPlugin.bufferType` default differs: webgi uses `UnsignedByteType` (`GBufferPlugin.ts:43`), threepipe also defaults to `UnsignedByteType` — same. But threepipe additionally exposes `bufferType: TextureDataType` constructor param and freezes after construction, while webgi was hardcoded.
- `GBufferPlugin.unpackExtension` registration on the screen pass is automatic in threepipe (only when `isPrimaryGBuffer`); webgi required external wiring.
- `FragmentClippingExtensionPlugin` — gltf extension name **changed**: webgi `'WEBGI_materials_fragment_clipping_extension'` (`FragmentClippingExtensionPlugin.ts:314`), threepipe `'WEBGI_materials_fragment_clipping'` (`src/plugins/material/FragmentClippingExtensionPlugin.ts:276`). Files exported by webgi will fail to import in threepipe and vice versa. Decide whether to keep both names registered for backward compat.
- `FragmentClippingExtensionPlugin` — webgi only allowed `MeshStandardMaterial2` and `isGBufferMaterial`; threepipe gates on `isPhysicalMaterial || isGBufferMaterial` (`src/plugins/material/FragmentClippingExtensionPlugin.ts:116`).
- `ClearcoatTintPlugin` — webgi explicitly only registered on `AssetManagerPlugin.materials`, not on gbuffer; threepipe matches. UI bounds for IOR are identical (`[0.8, 2.5]`).
- `NoiseBumpMaterialPlugin` — `parsFragmentSnippet` in webgi inlined `randomHelpers + voronoi + noiseBumpMatPars` in JS; threepipe consolidates into one `NoiseBumpMaterialPlugin.pars.glsl`. Verify the consolidated chunk includes equivalent `randomHelpers` (out of scope of this audit; see shader audit).
- `CustomBumpMapPlugin` — UI bounds for `_customBumpScale` widened from `[-1, 1]` (webgi) to `[-20, 20]` (threepipe). Threepipe also uses `appliedMeshes` (a getter on IMaterial) instead of `userData.__appliedMeshes`.
- `ParallaxMappingPlugin` — threepipe **removed** `@matDefine('PARALLAX_MAP_STEPS')` and `@matDefine('PARALLAX_MAP_B_STEPS')`. Now `stepCount` and `binaryStepCount` only feed the shader through string substitution into the loaded GLSL chunk (used for loop unrolling). This is cleaner but means cache key must include them — and threepipe correctly does (`src/plugins/material/ParallaxMappingPlugin.ts:94`). Webgi did NOT include them in cache key (`ParallaxMappingPlugin.ts:94` only includes `enabled` and `bumpMap?.uuid` and the debug toggles).
- `AnisotropyPlugin` (experiment) — adds `priority: 10`, `uuid: AnisotropyPlugin.PluginType` to the extension; webgi did not. Threepipe-webgi also uses `#include <randomHelpers>` (presumably resolved by the materials manager) instead of inlining `randomHelpers.glsl`.
- `AnisotropyPlugin` (experiment) `enableAnisotropy` is the new/canonical name; `makeAnisotropic` still exists as deprecated alias (line 372).
- `MeshOptSimplifyModifier` — threepipe returns non-indexed; webgi returns indexed (see Bugs).
- `VelocityBufferPlugin` — experiment auto-attaches its `unpackExtension` to `TemporalAAPlugin` via `viewer.forPlugin(...)` (lines 134-141). Webgi's TAA had its own wiring through `CombinedPostPlugin`. Cleaner.
- `VelocityBufferPlugin` — gone is webgi's traverse-and-flip-transparent loop; the experiment relies on `pass.preprocessMaterial` and `userData[VelocityBufferPlugin.PluginType]?.disabled` to opt out (line 113).
- `NormalBufferPlugin` — webgi's `NormalRenderPass2` flipped `material.transparent`/`transmission` per-frame to render opaque on transmissive objects. The threepipe port relies on `customNormalMaterial`/`customGBufferMaterial` slots and `pass.preprocessObject` (no per-frame mutation). Different opt-in model — projects relying on webgi's automatic transparent inclusion will need to set `customNormalMaterial`.
- `ProgressivePlugin` — completely refactored. Per-camera target Map (multi-camera scene support); `convergedPromise`; uses `AddBlendTexturePass`; legacy `jitter` config field is migrated to `SSAAPlugin.enabled` in `fromJSON` (`src/plugins/pipeline/ProgressivePlugin.ts:161-172`).

## API / signature drift

- `viewer.alert/confirm` → `viewer.dialog.alert/confirm` (everywhere; e.g. `src/plugins/material/FragmentClippingExtensionPlugin.ts:140`, `:197`).
- `material.materialObject` → just `material` (threepipe materials *are* `IMaterial`, not wrappers). Saves a level of indirection in every shader extender and uniform updater.
- `material.userData.__appliedMeshes` → `material.appliedMeshes` (a public getter).
- `webgi/helpers/material#shaderReplaceString` → `threepipe/utils#shaderReplaceString` (semantically equivalent).
- `webgi/helpers/serialize#serializeObject` / `deserializeObject` → `threepipe/utils#ThreeSerialization.Serialize` / `.Deserialize`.
- `AViewerPlugin<''>` (string-event-typed) → `AViewerPluginSync` (typed event map).
- `dependencies = [AssetManagerPlugin]` → no longer required (`v.assetManager` is always present on `ThreeViewer`).
- glTF loader registration: `manager.importer.addEventListener('loaderCreate', ...)` + push `extensions` array → single `v.assetManager.registerGltfExtension(...)` call with `{name, import, export, textures}` shape (`src/assetmanager/AssetManager.ts:579`). Threepipe ports systematically migrated; webgi still uses event-based.
- `manager.exporter.getExporter('gltf', 'glb').extensions.push(extExport)` → `assetManager.gltfExtensions[].export` field.
- `material.needsUpdate = true` after userData mutation → `material.setDirty?.()` (threepipe ports).
- `IShaderPropertiesUpdater` was a webgi-specific interface for "objects that update material uniforms before render"; threepipe wraps the same concept via `MaterialExtension.onObjectRender` + `extraUniforms` callbacks. Cleaner.
- `PluginType` constants — preserved across the port, so file-format compatibility holds for plugins that have been ported.
- `addNoiseBumpMaterial(material: Material)` (legacy) → `NoiseBumpMaterialPlugin.AddNoiseBumpMaterial(material: IMaterial, params?)`. Static method on plugin; takes typed userData.
- `enableCustomBump` / `enableAnisotropy` / `AddClearcoatTint` / `AddFragmentClipping` / `AddNoiseBumpMaterial` — all upgraded to `(material, params?)` signatures with optional partial-userData merge, return boolean (or partial userData).
- `GenericFilterPlugin.passCtor(v)` (webgi) → `PipelinePassPlugin._createPass()` (threepipe). The pass instance is owned by the plugin via `_pass` (serialized through `@serialize('pass')`).
- `IFilter<T,id>` wrapper interface dropped — `IPipelinePass` is the pass directly with `before`, `after`, `required`, `enabled`, `passId`.

## Notes / open questions

1. **Should the missing `FlatMaterialExtensionPlugin` be ported?** It depends on `GBufferPlugin` and modifies vertex `gl_Position`. The depthTest/depthWrite/renderToDepth/pluginsDisabled toggling is a useful pattern. Consider porting under `src/plugins/material/`.
2. **`LayeredMaterialPlugin`, `ThinFilmLayerPlugin`, `TriplanarUVMappingPlugin`, `AutoUVMappingPlugin`** — all material extensions with stable glTF extension names already in use. If you want full webgi parity they should be ported. They each have their own `WEBGI_materials_*` extension and may exist in user-saved glTFs in the wild.
3. **`AnisotropyPlugin` and `VelocityBufferPlugin` are in the experiment overlay only** — confirm whether they are intended for promotion to `src/plugins/`. The `AnisotropyPlugin` shaders are duplicated in both `experiments/webgi-legacy-src/plugins/shaders/` and `experiments/threepipe-webgi/src/plugins/extras/shaders/`. If promoting, dedupe.
4. **`XAtlasPlugin`** — depends on `xatlas-three` + `xatlasjs` (wasm). If desired in threepipe, decide on transitive dep size and whether to keep it as an opt-in plugin under `plugins/uv-unwrap/` similar to `plugins/path-tracing/`.
5. **The commented-out `unregisterMaterialExtensions` paths in `GBufferPlugin._disposeTarget` and `DepthBufferPlugin._disposeTarget`** — file as a known issue. The comment mentions a priority-ordering bug; verify whether it still reproduces before re-enabling. Likely root cause is that the screenPass `material` recomputes its extension list lazily; calling unregister between renders may cause an inconsistent state.
6. **`GBufferMaterial.onBeforeRender` per-frame `registerMaterialExtensions` / `unregisterMaterialExtensions`** — confirm whether shader recompilation is triggered by these calls. If yes, this is a per-object-per-frame perf hot spot. If not, it's still doing a Set delta.
7. **Confirm `flakeScale=0.05` default in `NoiseBumpMaterialPlugin`** is intentional (vs uniform default `1000`). UI bounds disagree.
8. **`FragmentClippingExtensionPlugin` glTF extension rename** is a breaking change. Either keep both names or document migration.
9. **`MeshOptSimplifyModifierPlugin._simplify` returning non-indexed geometry** — verify this is desired. If so, the comment in the abstract base (`SimplifyModifierPlugin.ts:140-148`) should be updated to reflect that subclasses are expected to return non-indexed.
10. **`GenericExtensionPlugin` / `MultiFilterPlugin`** — confirm there are no in-flight webgi plugins that still rely on `MultiFilterPlugin`. Pipeline plugins in scope all use either single-pass `PipelinePassPlugin` or the `IPipelinePass` interface directly.
