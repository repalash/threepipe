# Audit: Camera / Controls / Animation

Scope: camera-control plugins, camera-view animation, animation-object/popmotion/transform/gltf animation, frame fade, virtual cameras, plus webgi extras `animationObject.ts` / `butterScroll.ts`. Compared to threepipe core (`src/plugins/animation/`, `src/plugins/interaction/`, `src/plugins/rendering/VirtualCamerasPlugin.ts`, `src/plugins/pipeline/FrameFadePlugin.ts`, `src/core/camera/`, `src/three/controls/`, `src/utils/AnimationObject.ts`, `src/utils/animation.ts`) and `experiments/threepipe-webgi/src/`.

`experiments/threepipe-webgi/src/` has **no** camera/controls/animation plugins (only post-processing + extras), so it does not contribute to this audit.

## Summary

- All "thin" `ACameraControlsPlugin` wrappers (Pointer-lock, Device-orientation, Three-FirstPerson) are ported. **`ArcballControlsPlugin` and `TrackballControlsPlugin` are missing**: both webgi versions only require an `Arcball/Trackball Controls2` helper class behind them. The `FirstPersonControls` port in threepipe is renamed `ThreeFirstPersonControlsPlugin` (key `threeFirstPerson` instead of webgi's `firstPerson`). No `Arcball/Trackball Controls2` files exist under `src/three/controls/`.
- `CameraViewPlugin` is largely a superset in threepipe: serializable view event-bus (`setView`/`updateView`/`deleteView`/`animateView`), timeline-driven scrubbing, `animateToFitObject`, `getView/setView` on `ICamera`, `normalizeDuration`, etc. Webgi-only behaviors not yet ported: scroll/wheel parallax (`_wheel`, `_pointerMove`, `seekOnScroll`, `animateOnScroll`, `scrollAnimationDamping`, `rotationOffset` slider) — kept commented in `src/plugins/animation/CameraViewPlugin.ts` for later, and `recordAllViews`/CanvasRecorder integration. `splineCurve` UI dropdown (centripetal/chordal/catmullrom) is dropped; `createCameraPath` always uses `chordal`.
- `GLTFAnimationPlugin` in threepipe has a richer feature set (per-clip `clipData` with start-time / time-scale, page-scroll seek, multi-mixer per object, dispatch `addAnimation`/`removeAnimation`, integration with `viewer.timeline`) compared to webgi. **Webgi-only feature dropped**: `WEBGI_animation_markers` GLTF extension with `currentTimelineMarker` track, registered via `GLTFTimelineMarkersExtensionImport`/`glTFTimelineMarkersExtensionExport`. Threepipe has nothing for camera-attached timeline markers.
- `PopmotionPlugin` in threepipe added `animateNumber`, `animateCamera(Async)`, `timelineDriver`, `autoIncrementTime`, `pre/postFrame` updaters, `animateKeyframes` (offsets, repeat, repeatDelay), `createAnimationResult`. Webgi `animateSet`/`animateObject` exist in both but with different signatures.
- `AnimationObject` switched from `from`/`to` (webgi) to keyframed `values: V[]` + `offsets: number[]` (threepipe), with `addKeyframe`/`updateKeyframe`/`isValueSame` helpers and userData persistence. Threepipe `AnimationObjectPlugin` adds the click-to-trigger UI (◆ button), runtime animation registry (`runtimeAnimation` for objects/materials), undo manager integration, IntersectionObserver tracking. Webgi version is leaner. Anything reading the old `from`/`to` data is ported via the `fromJSON` migration shim (lines ~303–352 of `src/utils/AnimationObject.ts`).
- `TransformAnimationPlugin` is essentially identical (threepipe just adds `name`, `dependencies = [PopmotionPlugin]` and string/number/object getter `getSavedTransform`).
- `FrameFadePlugin` is ported with parity (event-driven on `mainCameraChange`/`materialUpdate`/`sceneUpdate`/`objectUpdate`, plus `_disabledBy` set kept on the parent `PipelinePassPlugin`). Threepipe additionally fires on `objectUpdate`. Webgi `pointerEnabled` is private `_pointerEnabled`; folded into `isDisabled()`.
- `VirtualCamerasPlugin` ported with parity + per-camera `IObjectExtension` UI buttons (Add/Enable/Remove) + `addTargetPreview` integration with `RenderTargetPreviewPlugin`. Webgi version had only `addCamera`.
- **Plugins not ported at all**: `ArcballControlsPlugin`, `TrackballControlsPlugin`, `ParallaxCameraControllerPlugin`, `CameraViewControlPlugin`, `ScrollableCameraViewPlugin`, `ScrollableCameraViewPreviewPlugin`, `CustomAnimationHelperPlugin`, `PosePlugin`, `BeringRingAnimation`, `ObjectRotationPlugin`, `butter.ts`/`butterScroll.ts`. Some are bespoke ring-store work (Bering, Pose) that may legitimately stay out; `ObjectRotation`, `Parallax`, `ScrollableCameraView`, `CameraViewControl` are general-purpose and are gaps.
- Confirmed already in threepipe (recent webgi sync items the user mentioned): `ICamera.setNearFar(near, far)` exists at `src/core/object/iCameraCommons.ts:243-254` (note: signature is `(camera, near, far, setDirty, source)` — internal helper called from RootScene; the public `setNearFar(near,far)` getter/setter pair exists on webgi's `CameraController` at `experiments/webgi-legacy-src/core/threejs/CameraController.ts:235-267`. Threepipe has no shadow state because the camera object IS the controller — `near`/`far` are the underlying three.js fields directly. TransformControls/Pivot detach() drag-end fixes are present in `src/plugins/interaction/TransformControlsPlugin.ts:155-186` and `PivotControlsPlugin.ts:165+`. Multi-select dummy world-space forcing handled in `src/plugins/interaction/MultiSelectHelper.ts:23-96`.

## webgi-only / new in webgi

- **`WEBGI_animation_markers` GLTF extension** (`experiments/webgi-legacy-src/plugins/GLTFAnimationPlugin.ts:549-655`): registers a `GLTFLoaderPlugin` to read `scene.extensions.WEBGI_animation_markers.markers[]`, and an exporter `glTFTimelineMarkersExtensionExport`; pushes a synthetic `AnimationClip('animationTimelineMarker', ...)` with a `NumberKeyframeTrack('.currentTimelineMarker', InterpolateDiscrete)`. Bound on `viewer.scene.modelRoot.currentTimelineMarker` to dispatch `animationTimelineMarker` and switch active camera. **Not present in threepipe** — gap.
- **CameraView scroll/seek interaction** (`CameraViewPlugin.ts:131-210`): `seekOnScroll`, `animateOnScroll`, `scrollAnimationDamping`, `rotationOffset` slider, `_pointerMove` for slight rotation, `_wheel` for direction. Threepipe has the wiring code commented out (`src/plugins/animation/CameraViewPlugin.ts:632-674`) and `rotationOffset` decorators commented (`:96-98`).
- **CameraView splineCurve dropdown** (`CameraViewPlugin.ts:117-120`): UI control for `centripetal`/`chordal`/`catmullrom` and full spline animation path. Threepipe `createCameraPath` (`src/core/camera/CameraView.ts:94`) hardcodes `chordal`.
- **CameraView `recordAllViews`** (`CameraViewPlugin.ts:312-358`): records to `CanvasRecorderPlugin`, integrates download via `FileTransferPlugin`. Threepipe has it commented out (`CameraViewPlugin.ts:737-792`).
- **Looping options**: webgi `viewLooping` decorator has `{limitedUi: true}`, `animDuration` and `animateAllViews` are `{limitedUi: true}`. Threepipe drops all `limitedUi` markers (cosmetic; relevant only if viewer/editor honors it).
- **`CameraViewControlPlugin` family** including damped state-based scrubber (`damping`, `enableDamping`, `initAnimationTime`, override start/end view animation), ScrollableCameraView (DOM section-based scroll mapping), preview plugin.
- **`ParallaxCameraControllerPlugin`**: asymmetric perspective frustum patched onto `cam.updateProjectionMatrix`, gyro/mouse `IInputDevice`, `_xDamper`/`_yDamper`, hooks `Picking.hitObject` for editing `focalPointHit`, `cameraView` linkage.
- **`ObjectRotationPlugin`**: persists `rotationCount`/`rotationSkips`/`rotationAxis`/`rotationOffset`/`rotationCurve` per object userData; supports arbitrary `Curve<Vector3>` derived from `RotationCurveDef` (`type:'circle'` default, extensible). Includes `auto-scale` integration via `autoScaleObject3D`. User flagged this as missing.
- **`PosePlugin`**: stable-pose detection from convex hull (Blender-style flat surface alignment), most-stable, vertical, next/previous pose helpers, debug visualization, ground sync.
- **`BeringRingAnimation`**: bespoke ring slot loader/animation; product-specific.
- **`CustomAnimationHelperPlugin`**: id-keyed map of `CustomAnimationHelper` instances with play/reverse APIs.
- **butter.ts** smooth-scroll wrapper.
- **`@uiToggle()`/`@uiSlider` `limitedUi: true`** option on FrameFade/CameraView/etc. — not present in threepipe; check whether `uiconfig.js` even still understands the flag.

## threepipe-only / new in threepipe

- **`CameraView` (`src/core/camera/CameraView.ts`) is now an `EventDispatcher`** with `setView`/`updateView`/`deleteView`/`animateView`/`update` events; webgi's `CameraView` is a plain class with arrow callbacks rebound by `CameraViewPlugin`. Threepipe also adds `zoom`, `isWorldSpace`, `clone()`. Hooks (`uiButton set/update/delete/animate`) dispatch events instead of calling plugin methods directly.
- **`CameraViewPluginEventMap`** (`viewChange`/`startViewChange`/`viewAdd`/`viewDelete`/`viewUpdate`/`update`) typed; webgi only has the first four as string-union template parameters.
- **`CameraViewPlugin.animateToFitObject`** (`src/plugins/animation/CameraViewPlugin.ts:422-444`) accepts arrays of object/material/texture/geometry; resolves applied meshes; supports `duration === 0` instant fit; uses `ICamera.fitObject`. Webgi version (`animateToFitObject`, `:696-702`) is single-object only and has no instant path.
- **`CameraViewPlugin.animateToView` accepts index/name/instance** (`:228-249`) and supports `normalizeDuration`. Webgi only takes a `CameraView` instance.
- **CameraView timeline scrubbing** (`_postFrame`, `:572-627`): if `viewer.timeline.shouldRun()` and views exist, drives camera position/target along `createCameraPath`. Webgi has no timeline integration — animation is purely promise-based via `_animationLoop`.
- **`PopmotionPlugin.animateCamera`** (`:384-414`) with optional `normalizeDuration` (skips/scales animation if travel distance is small relative to view distance), `timelineDriver` for keyframe playback driven by `viewer.timeline.time`, `animateKeyframes` (offsets, delay, canComplete), `animateNumber` with delta callback.
- **`GLTFAnimationPlugin` per-action `clipData`** (`uid`, `name`, `active`, `startTime`, `timeScale`) (`:803-811`) plus `autoUnpauseActions`, `autoEnableActions`, `activeActionWeight`, `inactiveActionWeight`, `stopOnCheckpointEnd`. Webgi has none of these — clips are mixed in/out monolithically.
- **`GLTFAnimationPlugin` `animateOnPageScroll`** + `pageScrollAnimationDamping`. Webgi only has the canvas-wheel `animateOnScroll`.
- **`GLTFAnimationPlugin` per-object animation list** (`_animations: IObjectAnimation[]` keyed by `object`) and `_objectRemove`/`_sceneUpdate` recompute (`:611-715`); reuses `clip.userData.clipActions[obj.uuid]` to avoid re-creating actions on re-import. Webgi creates new per-load mixers and dispatches a `dispose` listener via `obj.addEventListener('dispose', ...)`.
- **`AnimationObject` keyframe array** (`values`, `offsets`, `addKeyframe`, `updateKeyframe`, `isValueSame`, `getKeyframeValue`) + `repeatType` (`loop`/`reverse` only — `mirror` removed because of value-mirror gap, see `:240-242` comment) + serialization migration that maps old `{from, to}` to `{values:[from,to], offsets:[0,1]}` (`src/utils/AnimationObject.ts:303-352`).
- **`AnimationObjectPlugin` triggers** (`◆` button injection via `IntersectionObserver`, `_setupUiConfigButtons`, `setupUiConfigButton`, `_visibleBtns`), `runtimeAnimation` separate from `animation` for object/material-bound animations, undo integration, `userData.animationObjects` persistence on objects/materials, `getAllAnimations()`, `rebuildTimeline`/`getTimeline()`.
- **`PopmotionPlugin._preFrame`** + `timelineUpdaters` (`src/plugins/animation/PopmotionPlugin.ts:135-176`) for timeline-driven animations.
- **`TransformAnimationPlugin.getSavedTransform`** accepts `name: string` lookup; auto-names new transforms.
- **`VirtualCamerasPlugin._objectExtension`** (`:58-107`) adds three context buttons in the object UI (Add/Toggle/Remove virtual camera) and `removeCamera` API. Disposes target on remove. Auto-registers preview via `RenderTargetPreviewPlugin`.
- **`FrameFadePlugin` separate `FrameFadeBlendPass`** (`:184-230`) class and `_fadeObjectUpdate` (`:111-112`) for `frameFade: true` flag in `setDirty` options. Subclass-based `disable/enable` semantics moved to `PipelinePassPlugin`.
- **`ICamera.setView/getView`** (`src/core/object/iCameraCommons.ts`) avoids needing a separate plugin to read/write the view; `CameraViewPlugin` now delegates.

## Bugs in webgi

(only flagging the ones that show up while doing parity comparison; not auditing webgi as a whole)

- `CameraViewPlugin` `preFrame` listener never removed (`:180-205`) — there's no `viewer.removeEventListener('preFrame', ...)` in `onRemove`. Threepipe carries the same bug; there is even a `// todo: remove event listener` (`:114`).
- `CameraViewPlugin` `setCurrentCameraView` (`:427-435`) does not call `setDirty()` / does not refresh the camera matrix, only `positionUpdated()` — orientation may stick to the previous quaternion until interaction. Threepipe routes through `ICamera.setView` which calls `setDirty`.
- `CameraViewPlugin` `focusPrevious` early-returns when `_currentView` is undefined (`:471`) so first call after load does nothing; `focusNext` works. Threepipe inherits the same logic (`src/plugins/animation/CameraViewPlugin.ts:217`).
- `GLTFAnimationPlugin._objectAdded`: relies on `object.modelObject.userData.gltfAnim_SyncMaxDuration ?? this.syncMaxDuration` (`:225`) but mutates the userData unconditionally if syncing — potential surprising in-place mutation of clip durations on disk. Threepipe carries the same code (`:660-662`).
- `GLTFAnimationPlugin.onRemove` re-adds the `loaderCreate` listener instead of removing it (`:353` reads `addEventListener`). Threepipe doesn't track `loaderCreate` at all so the bug is moot.
- `ParallaxCameraControllerPlugin` duplicates `pointerdown`/`pointerup` listeners on every `onAdded` because it creates fresh bindings via `.bind(this)` (`:77-78`) without storing references — would leak if a viewer was added/removed multiple times.
- `CameraViewPlugin.animateToView` `try/catch` swallows `'Animation Stopped'` errors thrown by `onStop` callbacks via `Promise.allSettled` chaining; legitimate but easy to miss.
- `FrameFadePlugin` `passCtor` instantiates an inline class capturing `progressive` once (`:120-160`); `progressive.lastFrame` is read each frame inside it, but if `ProgressivePlugin` is removed at runtime the closure still references the stale instance.

## Bugs in threepipe

- **`PopmotionPlugin._postFrame` checks `Object.keys(this._updaters).length`** (`src/plugins/animation/PopmotionPlugin.ts:75`) but `_updaters` is an array — `Object.keys(array)` works but is wrong-by-style (would include any custom prototype keys). Webgi correctly uses `this.animations` keys (`PopmotionPlugin.ts:50`).
- **`PopmotionPlugin.onRemove` removes `postFrame` but not `preFrame`** (`src/plugins/animation/PopmotionPlugin.ts:186-189`). Webgi has only `postFrame` so no parity issue, but the threepipe `preFrame` registered at `:183` leaks.
- **`CameraViewPlugin` `preFrame` listener never removed** (`:115-126`) — same as webgi inheritance, but worse since the body is empty; can be deleted entirely.
- **`CameraViewPlugin.onAdded` doesn't track or remove window listeners** — comment block `// window.addEventListener('wheel'...)` is gone but `onRemove` (`:136-141`) still tries to remove the same commented-out listeners. Cleanup is symmetric to the dead code; not a leak today, but easy to flip on without re-adding. Worth a comment.
- **`GLTFAnimationPlugin._refreshAnimations` always pushes** (`:699`) even when `animation` already came out of `_animations.find`. This duplicates entries on every re-add: the `find` returns existing, the code mutates it in place, then `this._animations.push(animation)` adds another reference to the same object. Verify by `grep -n '_animations.push' src/plugins/animation/GLTFAnimationPlugin.ts`.
- **`GLTFAnimationPlugin._postFrame` action-weight logic** (`:561-564`) toggles weight using `!a1.weight` as the condition — for fractional starting weights (e.g. cross-fade) this misclassifies "active". Probably OK if `activeActionWeight` is exactly 1 / 0, but worth a flag.
- **`AnimationObjectPlugin._objectAdd`** does `e.object` may be undefined since the type is `{object?: IObject3D}`; the early `if (!obj) return` is OK, but `_setupUiConfig` is called even for `obj.isWidget` after the early return path — double-check the `isWidget` short-circuit at `:215`. Fine on read.
- **`VirtualCamerasPlugin` `preBlitCamera` event** types `readBuffer: WebGLTexture` (`:9`) but actually sends a `Texture` (`:46`). Mismatch with webgi which typed it as `readBuffer` carrying `.texture` (`:50`). Cosmetic but call sites can't compile-check.
- **`FrameFadePlugin._fadeObjectUpdate`** (`:111-112`) uses `ev.frameFade && ...` (truthy) but `ev.frameFade !== false && ...` for the other three fades. Inconsistent default — `objectUpdate` only fades when explicitly opted in, while the others fade by default. Likely intentional; document it.
- **`CameraViewPlugin.setDirty(ops)`** dispatches `{...ops, type: 'update'}` even when `ops` already has a `type` field (it gets overwritten by `type: 'update'`); fine but means callers cannot use a different event type. (`src/plugins/animation/CameraViewPlugin.ts:387`).

## Behavior divergences

- **CameraView storage**: webgi `viewId` was a module-level monotonic counter (`CameraViewPlugin.ts:28`) yielding `#view1`, `#view2`. Threepipe drops it; defaults to `'Camera View'` then `addCurrentView` overrides as `'View N'` based on length (`src/plugins/animation/CameraViewPlugin.ts:158`). Re-adds after deletes can collide.
- **`getCurrentCameraView` worldSpace**: webgi `worldSpace = true` default and parent inversion logic (`CameraViewPlugin.ts:391-403`); threepipe delegates to `ICamera.getView` (`src/core/object/iCameraCommons.ts:160-211`). Confirm both compute identical world-space `up`/`quaternion` for non-root parents.
- **Animation interpolation**: threepipe `animateCameraToViewSpherical` is in `src/utils` (resolved via `PopmotionPlugin.animateCamera`). Webgi's `lerpAngle` and `sphericalFromObject` are exported from `CameraViewPlugin.ts` so external code uses them. Threepipe must re-export equivalents from `src/utils/animation` if any external port relies on the names.
- **`focusView` deprecation**: threepipe marks `focusView` deprecated in favour of `animateToView` (`:564`). Webgi's API still uses `focusView`.
- **`CameraViewControl` style scrubber**: with `enableDamping`/`initAnimationTime`, the scrubber lerps `_oldState` → `_currentState` per frame and keeps the camera animated even after scroll input. No threepipe equivalent — `CameraViewPlugin` is event/promise-driven.
- **Spline duration**: webgi `CatmullRomCurve3(points, true, this.splineCurve, 0.75)` (closed loop, tension 0.75) (`CameraViewPlugin.ts:587`); threepipe `createCameraPath` uses the same closed/0.75 in `chordal` only (`src/core/camera/CameraView.ts:97`). Webgi's `splineCurve` UI choice is dropped.
- **Default ease**: both `easeInOutSine`, identical ease keys (`EasingFunctions` matches between `experiments/webgi-legacy-src/helpers/animation.ts:28-49` and `src/utils/animation.ts:41-62`). Confirmed by name list.
- **`animationSpeed` range**: both `[0.1, 4]`. **`timeScale` range**: both `[-2, 2]`. Identical.
- **Loop default**: webgi `loopAnimations = true`, threepipe `loopAnimations = true`. Same.
- **`autoplayOnLoad`**: webgi `false`, threepipe `false`. Threepipe adds a non-serialized `autoplayOnLoadForce` (`:156`).
- **`InteractionPromptPlugin` interaction**: webgi `CameraViewPlugin.animateToView` calls `interactionPrompt.stopAnimation({reset: true})` (`:511`); threepipe matches at `:259`.
- **`@onChange3('setDirty')` in threepipe `CameraViewPlugin`**: `viewPauseTime`/`animEase`/`animDuration`/`interpolateMode` re-render via `setDirty()` so timeline UI updates. Webgi does not have this → looping config changes don't re-render.
- **`AnimationObject.repeatType`**: webgi defaults to `'mirror'` (`AnimationObjectPlugin.ts:190`); threepipe defaults to `'loop'` and removed `'mirror'` from the dropdown options (`src/utils/AnimationObject.ts:240-247`). Saved files using mirror will fall back to loop.
- **`AnimationObject.access` migration**: threepipe migrates legacy paths (`scene.environment.rotation` → `scene.environmentRotation.y`, `scene.envMapIntensity` → `scene.environmentIntensity`) (webgi has the same shim at `:239-247`). Both check whether `access` is in the dropdown options whitelist (i.e. typing free-form access strings is reset). This is a regression from a generality standpoint — port should remove the `Object.values(options).includes(this.access)` whitelist if wanted (threepipe still has it at `:325` but only for viewer target).
- **GLTF animation post-frame**: webgi calls `v.scene.refreshActiveCameraNearFar()` after each frame (`GLTFAnimationPlugin.ts:196`). Threepipe drops this — relies on `RootScene` near/far update on `mainCameraUpdate` event chain.

## API / signature drift

- `ACameraControlsPlugin.onAdded/onRemove`: webgi `Promise<void>` async; threepipe `void` (sync subclass). Calling code that `await`s would still work but would wrap in resolved promise.
- `CameraViewPlugin.animateToView(view, duration?, easing?, throwOnStop?)` (webgi) vs `animateToView(_view, duration?, easing?, camera?, throwOnStop?, normalizeDuration?)` (threepipe). New positional args 4–6.
- `CameraViewPlugin.getCurrentCameraView(camera?, worldSpace?, view?)` (webgi) vs threepipe deprecates and routes to `getView(camera?, worldSpace?, view?)` — third arg `view?` for in-place update kept.
- `CameraViewPlugin` events: webgi string union `'viewChange'|'startViewChange'|'viewAdd'|'viewDelete'`. Threepipe added `viewUpdate` and `update`.
- `PopmotionPlugin.animate(options)` signature: webgi takes `AnimationOptions<V>`. Threepipe takes `AnimationOptions<V> & {target?, key?}` and an optional second arg `animateFunc` (`animate` or `animateKeyframes`). Callers that passed extra props (`target`/`key`) used `animateTarget` in webgi; threepipe folds them in.
- `PopmotionPlugin.animateObject(o, updaters, _external)` (webgi) vs `animateObject(o, delay?, canComplete?, driver?, delay2?)` (threepipe). Completely different. Code expecting webgi semantics (passing `updaters` map for `'scene'|'renderer'|'viewer'|'camera'`) breaks.
- `TUpdaterType`: webgi `'scene'|'renderer'|'viewer'|'camera'`; threepipe `(()=>void)`. Different shape: webgi addressed by name into a `Record<TUpdaterType, ()=>void>`, threepipe stores the callback functions directly.
- `IAnimationObject<V>`: webgi has `from?: V`, `to?: V|((v,target)=>V)`. Threepipe has `values: V[]`, `offsets?: number[]` (no `from`/`to`). Migration in `fromJSON` only.
- `AnimationObject` constructor: webgi `constructor(target: ValOrFunc<ViewerApp|undefined>)` single arg; threepipe `constructor(target?, getViewer?, name?)`. Older instantiations break.
- `extractAnimationKey` signature: webgi `(o, target?, extraGetters?)` returns `{key, tar}`; threepipe `(o, extraGetters?)` returns `{key, tar, onChange}`. `target` argument removed (threepipe pulls from `o.targetObject`).
- `VirtualCamerasPlugin.addCamera(camera)` (webgi) vs `addCamera(camera, target?, addTargetPreview?)` (threepipe). New optional args; new `removeCamera` method.
- `FrameFadePlugin` `disable/enable(name)` arg: webgi takes a `string`; threepipe accepts `string|object` (key on `this._disabledBy` is the source instance — see `src/plugins/base/PipelinePassPlugin.ts`). Strings still work.
- `CameraView` constructor: webgi `(position?, target?, up?, quaternion?, duration?)` and exposes `up`. Threepipe `(name?, position?, target?, quaternion?, zoom?, duration?, isWoldSpace?)` — `up` is gone (replaced by `quaternion`); `name` becomes first arg; `zoom` and `isWorldSpace` added. Direct `new CameraView(pos, target, up, quat)` from webgi will misalign.
- `ScrollableCameraView`/`CameraViewControl`: not present in threepipe.
- `setView` event dispatch: threepipe `CameraView.set/update/delete/animate` now dispatch on the `CameraView` itself; plugin listens via `addView`/`deleteView` (`src/plugins/animation/CameraViewPlugin.ts:163-187`). Webgi assigns arrow callbacks (`view.focusView = ...`) from the plugin (`CameraViewPlugin.ts:413-415`). Files saved from webgi will deserialize OK but the runtime hooks differ.

## Notes / open questions

- **`limitedUi: true` decorator option**: present on webgi `CameraView`, `CameraViewPlugin`, `GLTFAnimationPlugin`, `PopmotionPlugin` etc. It's stripped from threepipe ports. If `uiconfig.js` honors it for editor variant, the editor view-mode is degraded — verify before reintroducing.
- **`splineCurve` UI**: `createCameraPath` is hardcoded to `'chordal'`. Decide whether to expose `splineCurve: 'centripetal'|'chordal'|'catmullrom'` and a `tension` (webgi: 0.75 fixed) on `CameraViewPlugin` to match webgi.
- **`recordAllViews`**: needs porting only after a `CanvasRecorderPlugin` lands in threepipe (commented block in `src/plugins/animation/CameraViewPlugin.ts:737-792` is a ready template).
- **`WEBGI_animation_markers`**: do we want this in threepipe's GLTF importer/exporter chain? It's the only way camera-attached marker keyframes survive a round-trip. If yes, port `GLTFTimelineMarkersExtensionImport`/`glTFTimelineMarkersExtensionExport`. Decide on namespace — `WEBGI_animation_markers` vs `THREEPIPE_animation_markers`.
- **`ObjectRotationPlugin`**: explicitly flagged by user; no equivalent in threepipe. Note threepipe has `Object3DGeneratorPlugin`/`ObjectConstraintsPlugin` but neither provides rotated-mesh duplication. Port should keep userData persistence (`rotationCount`/`rotationSkips`/`rotationAxis`/`rotationOffset`/`rotationCurve`) and the extensible `RotationCurveDef` shape.
- **`ParallaxCameraControllerPlugin`**: depends on `IInputDevice` (gyro/mouse) and `Damper` (already in `ts-browser-helpers`). Asymmetric frustum patch is the gnarly part — patches `cam.updateProjectionMatrix` directly. Decide whether to do it via `BeforeRenderHook` or a `frustumOffset` field on `PerspectiveCamera2`.
- **`CameraViewControlPlugin` + `ScrollableCameraViewPlugin`**: tightly coupled; should be ported together. The damped scrubber semantics are different from `CameraViewPlugin.animateToView` and warrant a separate plugin (don't fold into CameraViewPlugin).
- **`PosePlugin`**: ConvexHull-based stable-pose detection is in `three/examples/jsm/math/ConvexHull` (already imported by threepipe via `addons.ts`). Port-feasible. Question: does any threepipe consumer need it? If not, skip.
- **`BeringRingAnimation`**: very product-specific (ring sub-models with `bmod` suffix). Should stay out of core threepipe.
- **`CustomAnimationHelperPlugin`**: only useful with `webgi/helpers/threejs/CustomAnimationHelper`; not in threepipe. Functionality already covered by `GLTFAnimationPlugin` per-clip APIs and `PopmotionPlugin`. Recommend skip.
- **`butterScroll`**: only used by ScrollableCameraView family. Skip unless porting that family.
- **Verify `near`/`far` parity**: threepipe `PerspectiveCamera2.near/far` setters call `setNearFar` internally? `grep` shows `setNearFar` only on `iCameraCommons.ts:243` (helper). Confirm `PerspectiveCamera2` exposes `setNearFar(near, far)` to match the webgi `CameraController.setNearFar` API (lines 235-267 of webgi CameraController). If not, third-party code calling `cam.setNearFar(...)` from webgi will fail.
- **`CameraViewPlugin.cameraViews` getter** (`:62`) is new; webgi only exposes `camViews` (`:97-99`). Threepipe keeps both for compatibility but the canonical name should be settled.
- **`AnimationObject.repeatType: 'mirror'`** removal — does any saved file rely on it? `fromJSON` will pass through unknown values into the property; runtime `animateKeyframes` may treat unknown as `'loop'`. Verify before removing the dropdown option for good.
- **Event-listener removal audit**: a fresh sweep of `addEventListener` vs `removeEventListener` on each plugin would surface a couple of leaks (CameraViewPlugin `preFrame`, GLTFAnimationPlugin webgi `loaderCreate`, PopmotionPlugin threepipe `preFrame`). Worth a mechanical pass.
- **`ACameraControlsPlugin` event name**: threepipe migrated `activeCameraChange` → `mainCameraChange` (`src/plugins/base/ACameraControlsPlugin.ts:14`). Any external consumer listening on `activeCameraChange` is broken.
- **`firstPerson` controls key rename**: webgi key `'firstPerson'` vs threepipe `'threeFirstPerson'`. If saved camera state references the controls key, it won't match. Decide whether to add `'firstPerson'` as an alias.
