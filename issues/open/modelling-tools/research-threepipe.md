```ts

```
This is the un-triangulated n-gon topology + per-corner UVs + per-face material slot — exactly what an editable mesh needs — but: (a) it is `__`-prefixed so it is dropped on clone and on glTF export; (b) it is built only on the mid path (not legacy, not 5.0 `attribute_storage`); (c) it is consumed only by the Subsurf modifier and then discarded (subdivided output has no cage); (d) mirror/array/solidify drop it (`issues/open/audit-blend-importer-modifiers-after-subsurf-lose-catmull-clark.md`).

## 9. Implications for modelling tools

Constraints (must be respected)
1. No editable mesh representation exists. Candidates in-repo are all partial: the svg-renderer half-edge (triangle-only ingest, no attributes, broken `splitEdge`, global `Array.prototype` patches, tests disabled), blend-importer's `Cage` (`positions/faces/uvs/materialIndices`, no edges/creases), procgen's three ad-hoc formats. A new, attribute-aware (point/edge/face/corner domains), n-gon topology type is required; kokraf's ID-indexed VEF Maps and Blender's `Mesh` (offset-indexed `corner_verts` + `poly_offset_indices` + named domain attributes — which the importer already parses) are the two concrete shapes to reconcile. Build it Node-safe (only `three` math/BufferGeometry imports).
2. Render model must stay a `BufferGeometry` on an `IObject3D` and be updated through the existing channels: `mesh.geometry = g` (accessor; auto-upgrade + `geometryChanged`) for replacement, or in-place `BufferAttribute.set` + `needsUpdate` + `geometry.setDirty({...})` for edits (AGeometryGenerator `updateAttribute` pattern). Use `{refreshScene: false}` during drags; full `setDirty()` on release. `appliedMeshes` is how to find all users of a geometry.
3. `__`-prefixed `userData` (where `__cage` lives now) is discarded on clone and export; `_`-prefixed is discarded on export. Topology that must persist needs a non-prefixed JSON key (auto round-trips via glTF `primitive.extras`) or a custom glTF extension with bufferViews registered via `assetManager.registerGltfExtension`. Viewer config never carries geometry.
4. Sub-object selection does not exist: `ObjectPicker.selectionMode` is object/material/texture/geometry, `HitIntersects` has no element ids, there is no BVH in core, and the modded `Raycaster` ignores `.visible` (gate pickers with layers or explicit lists). Element picking needs its own raycast path (BVH or custom edge/vertex screen-space tests) and a selection store separate from `ObjectPicker._selected` (which is object-level and undo-recorded).
5. Undo is closure-based (`undoManager.record({undo, redo})`, mutators returning undo fns) with a known stale-reference problem. Topology ops need proper commands (mesh deltas/snapshots keyed by mesh uuid, invalidated on dispose) rather than more closures over live objects.
6. Keyboard shortcuts are uncoordinated per-plugin `window` listeners with no modes; G/R/S (Blender) collide with Alt+G/R/S reset-transform, W/E/R gizmo modes, X/Y/Z axis toggles, H hide, F focus, P pivot-edit. Edit mode needs a mode-aware keymap layer (and to `disable()` object-mode plugins while active — `AViewerPlugin.disable(key)` exists for exactly this).
7. Widgets/handles added to the scene root trigger `sceneUpdate{hierarchyChanged}` and `refreshScene`; HierarchyUiPlugin filters `assetType==='widget'`, so overlays must be `assetType='widget'`/`isWidgetRoot` and must not create one `Mesh` per element (LineHelper's per-point Mesh is already flagged as needing instancing).
8. `EntityComponentPlugin` has three open bugs (uiConfig wipe on remove, strong Map, double-unregister crash); `IObjectExtension` (`isCompatible/getUiConfig/onRegister`) is the safer hook for per-object edit-mode state/UI today.
9. Bare `import 'threepipe'` is not Node-safe (`constants.ts:3` `ImageData`), and `src/core/{geometry,object}` value-import `ThreeViewer` for dialogs; a Node-safe modelling core must either live in a package subpath that never touches `threepipe`'s index (like `plugin-procedural-generation/graph`) or those imports must be made lazy (structural core change → ask first).
10. Blend import currently keeps the n-gon cage only on the 3.6–4.x path, only until Subsurf runs, and reads no edge-domain data; fan-triangulates concave n-gons incorrectly; the 5.0 path loses UV seams. An editable-mesh producer should replace the three triangulation loops with one "decode → EditableMesh → tessellate" routine and read `edata`/edge attributes.
11. `plugins/procedural-generation` is gitignored/uncommitted — do not depend on it from a shipped modelling plugin; port what is needed (its `extrudeFaces` is triangles-only anyway).
12. Every new example must be registered in `examples/index.html`, covered by a Playwright test with the same title (or excluded in `check-test-coverage.mjs`), and documented in `website/plugin/*.md` + sidebar. Interactive tests must drive Tweakpane/DOM, not `page.evaluate`.
